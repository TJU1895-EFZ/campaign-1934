# Campaign 1934 · 长征重大战役模拟

纪念中国工农红军长征胜利九十周年的桌面端网页体验。用户以第一人称进入飞夺泸定桥战场，在剧本化的人机战斗中理解战役背景与长征精神。

## 直接打开（推荐给普通用户）

**在线地址：https://tju1895-efz.github.io/campaign-1934/**

不需要 GitHub 账号，不需要安装任何软件：

1. 用桌面版 Chrome 或 Edge 打开上面的链接；
2. 点击画面锁定鼠标；
3. 按屏幕提示移动、瞄准、射击；
4. 完整流程约 5–8 分钟，战斗结束后有 5 道知识问答。

第一版只支持电脑端，不支持手机或平板。若学校或活动现场网络不稳定，可以让技术同学提前用下面的“本地运行”方式准备离线版本。

## 本地运行（开发者/离线演示）

```bash
npm install
npm run dev
```

浏览器打开终端提示的本地地址（默认 `http://127.0.0.1:5173`）。

生产构建：

```bash
npm run build
npm run preview
```

`npm run build` 会先执行 TypeScript 类型检查，再输出静态文件到 `dist/`。`dist/` 可以部署到任意静态托管服务，不需要后端。GitHub Release 也提供 `dist` 压缩包，适合离线演示；解压后需要用任意静态文件服务器打开，不能直接双击 `index.html`。

## 体验流程

```text
导读页
  → 战役总览页
  → 飞夺泸定桥（加载 → 第一人称战斗 → 战后知识问答 → 结算）
  → 返回总览 / 再次体验
```

- 导读页：长征背景、九十周年纪念、制作目的，正文底部“进入下一步”。
- 战役总览页：6 场长征重要战役卡片；第一版只有飞夺泸定桥可以进入，其余显示“即将开放”。
- 战斗：1 名真人玩家 + 15–20 名步兵人机；红军与国民党军外观可区分；Unity 战斗导演保证红军占优并固定胜利。界面显示当前阶段与任务。
- 三段地图：渡桥前是丛林接敌，中段是铁索桥与碉堡，过桥后进入街巷房屋战斗；桥只是整张地图的一部分。丛林有多条不明显小路，街巷加入垃圾桶、废弃军用车辆和房屋。
- 障碍与掩体：树木、房屋、车辆、垃圾箱等会阻挡移动和子弹；玩家可用 Space 跳过灌木、垃圾桶等低矮障碍；碉堡后有可见通道和台阶进入街巷。
- 人机行为：会侧移、找掩体、受击后短暂闪避，并以 3–5 发点射还击，而不是站桩对射。
- 射击表现：连发子弹之间有间隔；子弹飞行留下红色弹道火线；开枪有枪口火花；人机同样会连续射击。
- 桥面危险：玩家可从桥两侧坠落并触发“坠桥”；红军人机在桥上被击倒或失足时也会掉下桥。
- 人物表现：士兵拆分为上身和两条独立腿，移动时在髋部交替摆腿；加入背包、绑腿、军帽/头盔和步枪。环境按参考视频的雾谷、泥色河流、湿石与植被氛围调整。
- 碉堡防线：国民党军不在桥面上，而是据守对岸碉堡，从射击孔后还击；碉堡已加大，部分敌军站在碉堡顶的胸墙后，红军在桥上能更清楚地发现并射击敌军。
- 敌军强度：国民党军在每个阶段结束前会持续补充；还会周期性炮击红军所在区域，出现爆炸火球，可能炸死红军战士。
- 战线纪律：玩家过早冲进下一阶段区域或远离红军主体时，敌军会自然投入拦截兵力并以火炮覆盖，过程不显示系统惩罚提示，不能跳过剧本。
- 红军补充：红军即将耗尽或玩家复活时，会从当前战区后方以两个完整小队（共 8 人）成队加入，玩家和他们一起回到战线，进入地图后再分散到掩体间。
- 开场与结尾：玩家先在队伍中集结，号角响起约 3 秒后进入丛林；胜利后会看到国民党军残部乘坐车辆沿公路撤退，再进入知识问答。
- 受挫表现：第一波进攻受挫时，冲在最前面的红军人机会倒下，战线后移；玩家如果过分超前，也会被炮火击杀。
- 桥面与机枪：桥面缩短到约 60 米；弓形桥头工事的左、中、右三挺机枪高速压制桥面，每发造成 20 点伤害；第二波冲锋时红军突击队员用手榴弹摧毁机枪阵地，随后才突破。
- 剧本：丛林接敌 → 第一波突击受挫 → 第二波突击 → 街巷肃清。每个阶段有文字剧情和字幕。
- 战后知识问答：战斗结束后进入 5 道单选题，覆盖战役时间、铁索、勇士人数、河流和战役意义；答完显示得分，再进入结算。
- 结算：夺桥成功、历史意义、个人数据、知识问答得分、再次体验、返回总览。

## 胜利保障

红军一定胜利，并且由系统规则保证，不依赖玩家发挥：

- 红军人数始终多于国民党军（约 2:1）。
- 红军按阶段增援，国民党军补充有限。
- 关键突击队员倒下后自动补位。
- 战斗导演在红军减员过快时补充增援、降低敌军火力或触发敌军后撤。
- 唯一结局出口是 `red_victory`；玩家倒下只会触发负伤撤离和重生，不会触发失败。
- `BattleDirector` 的不变量有单元测试覆盖；`npm test` 包含静止、玩家反复倒下、高击杀、零命中等场景。

默认开启 `?debug=1` 可在开发环境查看阶段、人数、FPS、draw calls、导演修正值，并提供“跳过阶段”“直接胜利”按钮。生产构建不显示调试面板。

## 技术实现

- Unity 2022.3 LTS + URP（WebGL 战役场景）
- Vite + TypeScript（导读、总览、问答和结算外壳）
- 原生 DOM + CSS 界面
- Unity AudioSource 分层音频
- 剧情以文字字幕呈现，不使用语音播报
- 无后端、无账号、无第三方统计

### 目录

```text
src/
├─ app/                  HTML 外壳页面、导航及 Unity WebGL 嵌入
├─ content/              文案、战役数据、阶段配置
├─ styles/               设计变量、页面样式、战斗 HUD
└─ utils/                本地设置存储
unity/Campaign1934/
├─ Assets/Scripts/Core/  移植后的纯 C# 战斗规则
├─ Assets/Scripts/Runtime/ 玩家、人机、音频、视频投影与渲染
└─ Assets/Tests/         Unity EditMode / PlayMode 测试
public/unity/             可由 Unity 重新生成的 WebGL 构建
tests/e2e/               Playwright 界面测试
scripts/                 截图与性能检查工具（开发辅助）
```

### 性能

- 同场人数限制为 15–20，材质启用 GPU Instancing，视频在 60 米外自动暂停。
- 当前仓库内使用可复现生成的写实骨骼士兵模型（约 26K–29K 三角面），并启用 LOD、GPU Instancing、ACES、Bloom、暗角和 Film Grain。场景采用 URP Lit PBR 材质、法线/粗糙度贴图、雾谷和程序化 HDR 天空。

> **V1.1 变更**：技术栈从 Three.js 切换为 Unity WebGL，视觉目标为照片级真实（PBR + HDR + 后处理）。同场人机从 40 降至 15–20，目标 30+ FPS。详见 `docs/迭代需求-V1.1.md`。

### 测试

```bash
npm test          # Vitest：核心规则、导演不变量、页面组件
npm run test:e2e  # Playwright：Unity 加载、外壳导航、胜利消息、问答与结算
npm run lint      # TypeScript 类型检查
./scripts/build-unity-webgl.sh # 重新生成 public/unity/
```

当前 V1.1 测试覆盖：

- 伤害：100 血、单发 25 伤、4 发倒下、友军伤害无效、无部位倍率；连发、自动换弹、受击红边和低血常驻红边。
- 导演：初始部署、静止胜利、玩家反复倒下仍胜利、高击杀不跳过阶段、红军人数恢复、关键人机补位、人数上限、无失败路径。
- 阶段：4 个阶段顺序推进，使用生产阶段配置完成整场战斗。
- 页面：导读页、总览页 6 张卡片、锁定提示、返回导航。
- Unity EditMode：伤害、自动射击、炮击、空间规则、阶段强制完成、静止玩家胜利和玩家倒下不改变结局。
- Unity PlayMode：启动场景、15–20 人机预算、每名人机使用骨骼模型，以及三块独立视频投影屏。
- 端到端：Unity WebGL 画布加载、返回/重开、消息来源校验、胜利后 5 道知识问答、结算与刷新导航。

## 内容与素材

- 铁索桥、悬崖和铁索使用 Poly Haven 的 CC0 木纹、岩石、锈蚀金属纹理；其余场景、士兵、UI 图形由代码程序化生成。
- Unity 士兵由 MIT 许可的 Ara 3D Gen 在本地生成，底层 MakeHuman 人体资产为 CC0；红军使用灰蓝军装、布帽和运行时红袖标，守军使用土黄/橄榄军装与头盔。两套模型均带 Humanoid 骨骼和独立的站立、奔跑、下蹲、低姿移动动作，完整生成参数和许可证随模型保存。
- Unity 使用三个 AudioSource 逻辑总线播放项目方提供的 BGM、号角和 CC0 枪声；炮击落点使用 3D 空间音频。
- 外部音频仅使用上述 CC0 采样；未使用来源不明或授权不清的战争录音。
- 剧情文本来自 `PRD.md` 附录 A 的初稿，已写入 `src/content/narration.ts`。正式公开发布前，建议由项目方完成历史内容审核。
- `art/` 下的参考视频和图片只在本机用于视觉参考，已加入 `.gitignore`，不随项目分发；体验内人物与环境由程序化几何和 CC0 纹理重建。
- 三块场景投影屏使用项目方提供的战役视频剪辑成丛林、碉堡和街巷三个独立片段；只在对应阶段播放，60 米外暂停，并以 0.5 秒淡入淡出切换。详细来源与授权见 `docs/ASSET_LICENSES.md`。
- 字体使用系统字体栈，不随项目分发字体文件。

## 部署到 GitHub Pages

项目已配置相对资源路径和 GitHub Actions 工作流，可以直接部署到 GitHub Pages 项目站点（`https://<用户名>.github.io/<仓库名>/`）。

### 1. 推送到 GitHub

在 GitHub 创建一个空仓库，然后在本目录执行：

```bash
git init
git add .
git commit -m "chore: prepare GitHub Pages deployment"
git branch -M main
git remote add origin https://github.com/<你的用户名>/<仓库名>.git
git push -u origin main
```

### 2. 开启 Pages

进入仓库 **Settings → Pages → Build and deployment**，把 **Source** 设为 **GitHub Actions**。

推送后 `.github/workflows/deploy.yml` 会自动构建并发布，部署完成后访问：

```text
https://<你的用户名>.github.io/<仓库名>/
```

工作流也会在每次推送到 `main` 时自动更新。

### 3. 注意事项

- 公开仓库使用 GitHub Pages 最省事；私有仓库的 Pages 可能受 GitHub 套餐限制。
- 项目已经在 `vite.config.ts` 设置 `base: './'`，资源通过 `import.meta.env.BASE_URL` 加载，因此仓库子路径、用户站点根路径和自定义域名都能工作。
- 如果以后改成根目录站点（`<用户名>.github.io`），不需要改代码。
- 绑定自定义域名时，在 **Settings → Pages → Custom domain** 配置，并按 GitHub 提示设置 DNS。
- 构建产物在 `dist/`，由工作流生成，不需要提交到仓库。

### 手动部署

```bash
npm run build
```

也可以把 `dist/` 直接上传到任意静态托管。无需环境变量、数据库或服务器端接口。

## 备注

- 本项目是纪念性、教育性体验，不是竞技类产品。
- 历史结局固定，玩家的击杀数和命中率只影响结算页的个人数据。
- 页面内按钮是唯一权威导航；刷新页面回到导读页，不保存战斗进度。
- 音量、音效和字幕设置保存在浏览器本地存储。
