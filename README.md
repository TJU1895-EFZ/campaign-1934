# Campaign 1934 · 长征重大战役模拟

纪念中国工农红军长征胜利九十周年的桌面端网页体验。用户以第一人称进入飞夺泸定桥战场，在剧本化的人机战斗中理解战役背景与长征精神。

## 直接打开（推荐给普通用户）

**在线地址：https://tju1895-efz.github.io/campaign-1934/**

不需要 GitHub 账号，不需要安装任何软件：

1. 用桌面版 Chrome 或 Edge 打开上面的链接；
2. 点击画面锁定鼠标；
3. 按屏幕提示移动、瞄准、射击；
4. 完整流程约 5–8 分钟，战斗结束后有 5 道知识问答。

体验以桌面端键盘鼠标为主；触屏设备可使用左半屏虚拟摇杆、右半屏拖动瞄准和开火按钮完成基础操作。若学校或活动现场网络不稳定，可以让技术同学提前用下面的“本地运行”方式准备离线版本。

## 本地运行（开发者/离线演示）

```bash
npm install
npm run dev
```

浏览器打开终端提示的本地地址（默认 `http://127.0.0.1:5173`）。

生产构建：

```bash
npm run build
npm run preview
```

`npm run build` 会先执行 TypeScript 类型检查，再输出静态文件到 `dist/`。`dist/` 可以部署到任意静态托管服务，不需要后端；离线演示时请用任意静态文件服务器打开，不能直接双击 `index.html`。

## 体验流程

```text
导读页
  → 战役总览页
  → 飞夺泸定桥（加载 → 第一人称战斗 → 战后知识问答 → 结算）
  → 返回总览 / 再次体验
```

- 导读页：长征背景、九十周年纪念、制作目的，正文底部“进入下一步”。
- 战役总览页：6 场长征重要战役卡片；第一版只有飞夺泸定桥可以进入，其余显示“即将开放”。
- 战斗：1 名真人玩家 + 同场最多 40 名步兵人机（红军 20–26 名，国民党军 10–14 名）；红军与国民党军外观可区分；战斗导演保证红军占优并固定胜利。界面显示当前阶段与任务。
- 三段地图：渡桥前是丛林接敌，中段是铁索桥与碉堡，过桥后进入街巷房屋战斗；桥只是整张地图的一部分。
- 障碍与掩体：树木、房屋、车辆、垃圾箱等会阻挡移动和子弹；玩家可用 Space 跳过灌木、垃圾桶等低矮障碍；红军人机撞上掩体时会停下，不会原地继续迈步。
- 人机行为：会侧移、找掩体、受击后短暂闪避，并以 3–5 发点射还击，而不是站桩对射。
- 射击表现：连发子弹之间有间隔；子弹飞行留下红色弹道火线；开枪有枪口火花；人机同样会连续射击。
- 桥面危险：玩家可从桥两侧坠落并触发“坠桥”；红军人机在桥上被击倒或失足时也会掉下桥。
- 人物表现：士兵拆分为上身和两条独立腿，移动时在髋部交替摆腿；加入背包、绑腿、军帽/头盔和步枪。环境按参考视频的雾谷、泥色河流、湿石与植被氛围调整。
- 碉堡防线：国民党军不在桥面上，而是据守对岸碉堡，从射击孔后还击；碉堡已加大，部分敌军站在碉堡顶的胸墙后，红军在桥上能更清楚地发现并射击敌军。
- 敌军火力：国民党军在每个阶段结束前会持续补充；还会周期性炮击红军所在区域，炮弹实体从对岸方向划过空中、带烟雾拖尾，落地爆炸并可炸死红军战士。
- 战线纪律：玩家过早冲进下一阶段区域或远离红军主体时，敌军会自然投入拦截兵力并以火炮覆盖，过程不显示系统惩罚提示，不能跳过剧本。
- 红军补充：红军即将耗尽或玩家复活时，会从当前战区后方以两个完整小队（共 8 人）成队加入，玩家和他们一起回到战线，进入地图后再分散到掩体间。
- 开场与结尾：玩家先在队伍中集结，号角响起约 3 秒后进入丛林；战斗开始播放项目方提供的背景音乐，夺桥成功后音乐停止。胜利后能看到国民党军残部乘坐车辆沿公路撤退，再进入知识问答。
- 受挫表现：第一波进攻受挫时，冲在最前面的红军人机会倒下，战线后移；玩家如果过分超前，也会被炮火击杀。
- 桥面与机枪：桥面缩短到约 60 米；弓形桥头工事的左、中、右三挺机枪高速压制桥面，每发造成 20 点伤害；第二波冲锋时红军突击队员用手榴弹摧毁机枪阵地，随后才突破。
- 剧本：丛林接敌 → 第一波突击受挫 → 第二波突击 → 街巷肃清。每个阶段有文字剧情和字幕；从碉堡突入街巷时有约 8 秒的冲锋过场，结束后恢复玩家控制。
- 战后知识问答：战斗结束后进入 5 道单选题，覆盖战役时间、铁索、勇士人数、河流和战役意义；答完显示得分，再进入结算。
- 结算：夺桥成功、历史意义、个人数据、知识问答得分、再次体验、返回总览。

## 胜利保障

红军一定胜利，并且由系统规则保证，不依赖玩家发挥：

- 红军人数始终多于国民党军。
- 红军按阶段增援，国民党军补充有限。
- 关键突击队员倒下后自动补位。
- 战斗导演在红军减员过快时补充增援、降低敌军火力或触发敌军后撤。
- 唯一结局出口是 `red_victory`；玩家倒下只会触发负伤撤离和重生，不会触发失败。
- `BattleDirector` 的不变量有单元测试覆盖；`npm test` 包含静止、玩家反复倒下、高击杀、零命中等场景。

开发环境下可通过 `?debug=1` 打开调试面板，查看阶段、FPS、draw calls、导演修正值，并使用“跳过阶段”“直接胜利”按钮。生产构建默认不显示调试面板。

## 技术实现

- Three.js 0.186 + WebGL 第一人称战斗场景
- Vite 8 + TypeScript 7
- 原生 DOM + CSS 界面
- Web Audio API 分层实时合成音效；战斗背景音乐使用项目方提供的 `battle_bgm.mp3`
- 剧本、阶段、伤害、炮击、前线与胜利保障等规则位于纯 TypeScript 核心层，可独立单测
- 无后端、无账号、无第三方统计
- 桌面键盘鼠标为主，触屏设备提供基础虚拟摇杆操作

### 目录

```text
src/
├─ app/                  应用状态机与页面：导读、总览、战斗、问答、结算
├─ battle/core/          纯规则层：战斗导演、阶段、伤害、前线、炮击、碰撞、常量
├─ battle/runtime/       Three.js 运行时：战斗循环、玩家控制、武器、人机、HUD、音频
├─ battle/three/         场景搭建与士兵模型
├─ content/              文案与配置：战役卡片、导读、播报、阶段、问答、结算
├─ styles/               设计变量、页面样式、战斗 HUD
└─ utils/                本地设置存储
tests/e2e/               Playwright 端到端测试
scripts/                 截图、录制、检查、性能测量等调试脚本
public/assets/           CC0 纹理、音频、视觉参考素材（详见 public/assets/README.md）
docs/                    授权说明与归档文档
```

### 性能

- 同场人机上限 40 名，士兵为合并几何 + 顶点色的低多边形模型，共享材质。
- 按实测帧率自动调整渲染像素比（0.6–1.5），低帧率时优先保证流畅。
- 场景使用程序化几何、CanvasTexture 与雨雾效果，不依赖外部 3D 模型即可运行。
- 端到端测试使用 SwiftShader 软件渲染，其中的 FPS 数字不代表真实硬件表现。

### 测试

```bash
npm test          # Vitest：核心规则、导演不变量、阶段、炮击、页面组件
npm run test:e2e  # Playwright：完整导航、暂停、胜利问答、街巷阶段
npm run lint      # TypeScript 类型检查
npm run build     # 类型检查 + 生产构建
```

当前测试覆盖：

- 规则：100 血、单发 25 伤、4 发倒下、友军伤害无效、无部位倍率；连发、换弹与 HUD 状态。
- 导演：初始部署、静止胜利、玩家反复倒下仍胜利、高击杀不跳过阶段、红军人数恢复、关键人机补位、人数上限、无失败路径。
- 阶段：4 个阶段顺序推进，使用生产阶段配置完成整场战斗。
- 战斗系统：前线纪律、炮击伤害与落点判定、碉堡机枪、碰撞、人机移动与掩体阻挡、炮击弹道。
- 页面：导读页、总览页 6 张卡片、锁定提示、返回导航、问答与结算。
- 端到端：导读→总览→Three.js 战斗、锁定战役卡片、暂停/继续/重开/返回总览、胜利后 5 道问答与结算、街巷阶段过场结束后恢复控制、刷新回导读。

单元测试共 19 个文件、83 个测试；端到端测试 7 个用例。

## 第一版范围

已完成：导读、总览、飞夺泸定桥第一人称战斗、剧本阶段与字幕、战斗背景音乐、红军必胜保障、负伤重生、结算、暂停与音量设置、战后知识问答、性能自适应、触屏基础操作、GitHub Pages 部署。

## 内容与素材

- 铁索桥、悬崖和铁索使用 Poly Haven 的 CC0 木纹、岩石、锈蚀金属纹理；其余场景、士兵、UI 图形由代码程序化生成。
- 士兵使用合并几何 + 顶点色的低多边形模型，红军为灰蓝军装与红袖标，国民党军为土黄军装与头盔。
- 音效以 Web Audio API 分层实时合成为主：近距步枪、跳弹、爆炸、河风、脚步、远处炮火与胜利和弦；战斗背景音乐和号角等素材由项目方提供。
- 远处/断续枪声使用 OpenGameArt 的 CC0 枪声采样随机片段，带左右声像。
- 剧情文本来自 `PRD.md` 附录 A 的初稿，已写入 `src/content/narration.ts`。正式公开发布前，建议由项目方完成历史内容审核。
- `public/assets/reference/` 下的参考图片与影视资料由项目方提供，仅用于视觉参考，不参与构建。`.gitignore` 中的本地参考目录同样不随项目分发。
- 字体使用系统字体栈，不随项目分发字体文件。
- 详细来源与授权见 `docs/ASSET_LICENSES.md` 和 `public/assets/README.md`。

## 浏览器

- 推荐最新版 Chrome / Edge，桌面端。
- 需要 WebGL 和 Pointer Lock 支持。
- 桌面端使用键盘鼠标；触屏设备提供基础虚拟摇杆和开火按钮，移动端布局与性能尚未专门优化。
- 首次点击画面后锁定鼠标；按 Esc 释放。

## 部署到 GitHub Pages

仓库已配置 GitHub Actions（`.github/workflows/deploy.yml`）：推送到 `main` 后，工作流会在 Node 22 环境执行 `npm ci` 和 `npm run build`，并把 `dist/` 发布到 GitHub Pages。线上地址：

```text
https://tju1895-efz.github.io/campaign-1934/
```

- Pages 的 **Source** 需设为 **GitHub Actions**。
- `vite.config.ts` 使用 `base: './'`，资源通过 `import.meta.env.BASE_URL` 加载，仓库子路径和自定义域名都能工作。
- 构建产物在 `dist/`，由工作流生成，不提交到仓库。
- 也可以把 `dist/` 上传到任意静态托管服务，无需环境变量、数据库或服务器端接口。

## 备注

- 本项目是纪念性、教育性体验，不是竞技类产品。
- 历史结局固定，玩家的击杀数和命中率只影响结算页的个人数据。
- 页面内按钮是唯一权威导航；刷新页面回到导读页，不保存战斗进度。
- 音量、音效和字幕设置保存在浏览器本地存储。
