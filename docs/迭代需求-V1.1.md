## 3. A 组 · 音频

### A1 导读页背景音乐

- 音乐：情绪激昂的纯音乐（红色题材风格），伴奏循环，首尾各 2 秒淡入淡出。
- 范围：导读页与总览页播放；进入战斗加载页 / 战斗页时停止并释放。
- 播放时机：必须在用户首次交互后才能开始（浏览器自动播放策略），
  首次点击或按键时解锁 `AudioContext` 并起播。
- 实现位置：**新建应用级音频模块**（例如 `src/audio/AppAudio.ts`）。
  当前 `AudioManager` 只在 `BattleRuntime` 内实例化（`BattleRuntime.ts:88`），
  导读页与总览页没有任何音频能力，不能直接复用。
- 控件：导读页提供静音 / 恢复按钮，不遮挡正文与底部按钮，状态存 localStorage。
- 验收：导读页停留 3 分钟无爆音、无卡顿、循环接缝无咔哒声；静音按钮即时生效；
  进入战斗后音乐完全停止。

### A2 战役卡片悬停音效

- 可进入卡片（飞夺泸定桥）：短促清亮的音效，时长 ≤ 0.25 秒。
- 锁定卡片（其余 5 张）：明显不同的低沉短音。
- 节流：200ms 内不重复触发，鼠标快速划过多张卡时不连成一片。
- 键盘 Tab 聚焦时触发同样音效（无障碍，PRD FR-2.5 要求键盘可操作）。
- 验收：快速划过 6 张卡只触发有限次数；音量明显低于战斗音效。

### A3 玩家枪声音量

- 问题：默认音量下玩家射击声偏轻，质感偏弱。
- 原因（`AudioManager.ts`）：玩家枪声 `playRifle()` 是 Web Audio 程序化合成，
  而远处枪声 `playDistantShot()` 用的是 CC0 采样 `guns.mp3`，两者质感不一致；
  且环境底噪叠了三层循环噪声，盖住了枪声。
- 要求：
  ① 近距射击改用与 `guns.mp3` 一致的采样质感（或叠加一层采样）；
  ② 新增独立的 weapon 子总线，使枪声可脱离环境音单独调节；
  ③ 保留连发间隔，不得因提高音量产生爆音或削波。
- 验收：默认设置下连发时枪声清晰盖过风雨 / 河水底噪；
  连续射击 30 发无爆音、无卡顿。

### A4 战斗环境音增强

- 炮弹落地爆炸：把爆炸音效**绑定到炮击落点**（`src/battle/core/artillery.ts`），
  按落点距离做音量衰减与声像定位，取代现在"背景里响一声"的做法。
- 冲锋呐喊：红军发起冲锋时触发。每波冲锋触发一次，8 秒内不重复，
  音量不超过爆炸声。播报期间遵循现有 ducking 规则降到约 40%。
- 验收：炮弹落点与爆炸声位置一致；呐喊不抢戏、不循环轰炸耳朵。

## 4. B 组 · 人机动效

### B1 静止 / 卡住时停止奔跑动作

- 问题：人机撞到障碍物或静止不动时，腿部仍在摆动。
- 根因（`BotManager.ts:269`）：`setMoving` 按 `distance > 0.4 && state === 'advance'`
  判断。撞墙时 `targetZ` 仍有距离，所以位移被挡住了腿还在摆。
- 要求：实际位移连续 0.3 秒低于 0.05 米时，强制停止腿部摆动与上身起伏。
- 验收：把人机逼到树 / 房屋 / 垃圾箱前，1 秒内腿部动作归零；脱困后恢复正常。

### B2 新增下蹲、匍匐姿态

- **不要塞进 `BotState`**。当前 `BotState` 只有
  `advance / hold / retreat / downed / falling`（`BotManager.ts:38`），
  姿态应作为**正交字段**新增：`stand / crouch / prone`。
- 速度倍率：下蹲约 0.5，匍匐约 0.25。
- **碰撞盒不改变**，本次只做视觉表现，避免动到命中判定、破坏战斗平衡。
- 验收：三种姿态在 30 米外可分辨；切换平滑无抖动；
  40 人机同场下帧率不低于 30 FPS。

### B3 撞到障碍物时的躲避决策

- 规则：撞到障碍物时，50% 概率下蹲躲避，50% 概率站立绕行
  （概率写成可配置常量，便于调手感）。
- 下蹲躲避持续 0.8–1.5 秒后恢复推进；绕行则侧向移动后再推进。
- 验收：观察 10 次撞击两种行为都出现，不出现原地卡死超过 2 秒。

### B4 过桥时的奔跑 / 匍匐混合

- 桥面冲锋中的红军人机，约 2/3 快速奔跑、约 1/3 匍匐前进。
- 验收：桥面上能同时看到两种姿态，比例大致符合。

## 5. C 组 · 过桥节奏（已定的设计取舍）

### C1 冲锋节奏

- 桥面段红军人机速度：从当前 1.25–1.8 m/s（`BotManager.ts:110`）
  提高到 **3.2–4.0 m/s**。
- 编组：每次投入 **2–3 人**向前冲；前方倒下后 0.8–1.5 秒补上下一组。
- 桥上红军同时存在人数**硬上限 5 人**；达到上限后后续编组在桥头待命，
  不提前上桥。
- 验收：任意时刻桥面红军 ≤ 5 人；能看到"冲上去—倒下—再冲上去"的连续节奏。

### C2 "受挫"的表现方式（已定，不再靠减速）

- 阶段 2 的剧本是"第一波突击受挫"，但提速后不能靠"冲得慢"来表现受挫。
- **改用**：投入的编组大量倒在桥面 + 推进距离长时间停滞在桥中段。
- 桥面段总时长（阶段 2 + 阶段 3）需与新节奏重新对齐。
- 约束：单局总时长控制在 ≤ 10 分钟。

## 6. D 组 · 阶段过渡

### D1 丛林阶段：打完再走

- 现状：`phase_1` 为 `durationSec: 50`、`endCondition: 'timer'`，
  导致红军还没打到桥头就切到下一阶段。
- 修改：
  ① 丛林阶段时长延长到约 90 秒；
  ② 结束条件从"计时"改为"丛林守军被清空 **且** 红军前锋推进到桥头"；
  ③ 丛林段国民党军停止增援（当前配置 `initial: 12, reinforcements: 8`），
     "全部杀掉"指这 12 名初始守军；
  ④ **必须保留超时兜底**：90 秒仍未达成条件时强制进入下一阶段。
- **为什么必须保留兜底**：PRD AC-09 要求玩家完全不操作时剧本仍要走完并胜利。
  改为状态条件后，玩家挂机且红军清不完敌人就会卡死在丛林段。
- 引导：用字幕与任务提示引导玩家向桥头移动，不要使用火炮驱赶。
- 验收：正常推进下看到守军被清空并抵达桥头后再过渡；挂机 90 秒后仍能自动进入桥面段。

### D2 碉堡 → 街巷：先锋冲入过场

- 现状：从"进攻碉堡"直接切到"街道肃清"，过渡生硬。
- 修改：在阶段 3 末尾 / 阶段 4 开头插入 6–10 秒过场——
  2–4 名红军突击队员从桥头冲入碉堡，与内部守军短兵相接，随后主力跟进进入街巷。
- 玩家处置：过场期间**临时禁用**"脱队被拦截 / 炮击"的惩罚（PRD FR-3.24）；
  玩家若停留在桥面，用字幕与战友喊话引导，不要用火炮驱赶。
- 验收：能看清先锋冲入碉堡的过程；过场期间玩家不会被惩罚；过场不卡死。

## 7. E 组 · 场景内视频投影（本次新增）

### E1 呈现形式

- 使用 Three.js `VideoTexture` 把视频贴在场景物体表面。
- **不做**全屏叠加、**不做** HUD 角落小窗。
- 理由：全屏叠加要同时跑视频解码和 3D 渲染，会把 40 人机的场景拖到 30 FPS 以下；
  场景内投影对帧率几乎无影响，也不打断指针锁定。
- 内容主题：项目方自制 / AI 生成的战役画面。项目整体走**写实路线**（见 §8 F 组），
  视频与 3D 场景都应写实、风格统一。

### E2 屏幕绑定剧情，不固定常亮

三块屏幕物理位置固定，但**只在对应剧本阶段点亮播放**，其余时间熄灭。
玩家推进到哪一段，哪一块屏幕亮起——影像跟着剧情走，而不是固定在原地常播。

| 剧本阶段 | 点亮的屏幕 | 位置 | 场景代码 |
| --- | --- | --- | --- |
| 阶段 1 丛林接敌 | 丛林宣传牌 | 丛林区域，需新建立式牌面 | 朝向玩家来向，立在路边 |
| 阶段 2/3 桥面突击 | 对岸碉堡正面墙 | `BUNKER_WALL_Z ≈ -31.5` | `SceneFactory.ts:47` |
| 阶段 4 街巷肃清 | 街巷房屋墙面 | 街巷区域（`z ≈ -70`） | `SceneFactory.ts:852` |

- 切换时机：挂在 `BattleRuntime.handlePhase()` 上——阶段切换时，上一块屏幕淡出熄灭，
  当前阶段对应的那块淡入亮起。
- 如果希望"同一块屏幕在不同阶段播放不同影像"，按 `vid_phase_1..4.mp4` 命名素材，另计。

### E3 技术要求

- `HTMLVideoElement` 必须设置 `muted` + `loop` + `playsInline` 才能自动播放。
- **视频本身静音**，声音由 Web Audio 单独处理，避免与战斗音效冲突。
- 只创建 3 个 `VideoTexture`，不做动态增删。
- 距离 > 60 米时暂停该视频元素的更新以省性能。
- 非当前阶段的屏幕不播放视频（只显示静态底图或熄灭），降低显存与解码占用。
- 阶段切换时屏幕用约 0.5 秒淡入淡出，不要硬切。
- 素材未到位时，用 `CanvasTexture` 生成占位画面（纯色 + 说明文字）。
- 验收：每段都能看到对应屏幕亮起；阶段切换有过渡；战斗全程帧率不低于 30 FPS。

## 8. F 组 · 视觉方向：写实路线（方案已定：保持 Three.js，写实 PBR + 后处理）

> **方向已定（2026-10-24）：采用方案 A——保持 Three.js，向写实路线推进。**
> 接受"高度写实、非严格意义照片级"，换取保留网页形态与现有核心逻辑。
> 本节是对 `PRD.md` FR-3.6「风格化低多边形」的有意推翻，接手方必须同步更新 PRD。

### F1 为什么选 A

- 「照片级真实」「网页免安装」「40 人机 30+ FPS」三者不可兼得。
- 现有架构刻意把战斗逻辑放在 `src/battle/core/`（纯 TypeScript，与渲染解耦，
  见 `HANDOFF.md` §5）。**方案 A 只需重写渲染层（`three/`、`runtime/`），
  战斗逻辑、导演、胜利保障和全部测试都能保留。**
- 方案 B（Unity WebGL）与 C（Unreal / 原生桌面）都要推翻 V1 全部代码重做，
  B 仍是网页但更重，C 放弃网页——**已放弃**。
- 若 A 的写实度实测达不到预期，再评估是否升级到 C；届时 V1 代码仍可用作逻辑参考。

### F2 写实路线的具体做法（只动渲染层）

- **模型**：红军 / 国民党军士兵、铁索桥、碉堡、山体、河流、街巷房屋，
  从程序化低多边形改为写实 PBR GLB 模型（albedo / normal / roughness / metalness / ao
  贴图 + 骨骼动画）。士兵当前由 `SoldierView.ts` 合并几何生成，场景由 `SceneFactory.ts` 程序化生成。
- **光照**：HDR 环境光照 + 方向光 + tonemapping。
- **后处理**：bloom、SSAO、film grain、暗角，营造写实氛围。
- **UI / HUD**：随场景写实化协调调整，保持庄重，避免廉价满屏红（PRD FR-1.3）。

### F3 新增素材（项目方提供，接手方不要自制）

在 §1 清单基础上追加 3D 模型：

| 文件 | 用途 |
| --- | --- |
| `public/assets/models/soldier_red.glb` | 写实红军士兵（PBR + 骨骼动画） |
| `public/assets/models/soldier_kmt.glb` | 写实国民党军士兵 |
| `public/assets/models/env_bridge.glb` | 写实铁索桥 / 桥头堡 |
| `public/assets/models/env_street.glb` | 写实街巷房屋 |
| PBR 纹理若干 | 替代现有 CC0 1K 低分辨率纹理 |

### F4 性能红线（写实后最吃紧的一条）

- 「40 人机同场不低于 30 FPS」仍是硬约束，但写实模型面数高得多。
- 当前性能预算按低多边形制定（单兵 ≤2000 三角形、场景 ≤150,000 三角形，
  见归档 `docs/archive/DEV_PLAN.md` §3.9）——**写实后必须重新定面数上限，并用真实硬件实测，不能照搬。**
- 若实测不达标，允许把同屏人机降到约 15–20 名，并相应更新 PRD 的人数约束（VR-1、AC-07）。
  **这是写实路线下的唯一让步，人数下限需用户确认后再动。**

### F5 内容与史实红线

- 无断肢、无喷血，倒地 / 受击表现克制（`PRD.md` §7.7）。写实后更易踩线，务必克制。
- 历史表述仍以权威公开资料为准（`PRD.md` §5.6）。
