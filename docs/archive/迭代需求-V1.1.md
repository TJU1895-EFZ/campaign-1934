## 1. 技术栈变更：从 Three.js 到 Unity WebGL

### 1.1 变更原因

V1 使用 Three.js（WebGL）实现，视觉风格为"风格化低多边形"。V1.1 的目标是**照片级真实**——让场景和人物像照片一样真实。Three.js 要实现这个目标需要重写全部渲染管线、加载写实 GLB 模型、配置 PBR 材质和 HDR 后处理，且 WebGL 性能上限有限，40 个写实士兵同场很难维持 30 FPS。

**Unity WebGL 是更合适的选择：**
- 内置 HDRP/URP 渲染管线，开箱即支持写实光照、后处理、PBR 材质
- 模型导入、骨骼动画、材质编辑有完整编辑器工具链
- WebGL 导出成熟，体积和性能优化方案丰富
- 视觉质量与性能的平衡点远高于 Three.js 手写管线

### 1.2 变更范围

**需要重写：**
- 全部渲染层（场景、士兵外观、环境、后处理）
- 玩家控制、武器、人机 AI 的运行时表现层
- HUD（可保留 DOM 叠加方案，用 Unity UI Canvas + HTML 混合）
- 音频（Unity AudioMixer 替代 Web Audio API）
- 构建部署流程（Vite → Unity WebGL Build）

**尽量保留：**
- 战斗规则逻辑（`src/battle/core/` 下的纯函数）——可移植为 C# 类或作为独立 DLL 供 Unity 调用
- 文案与配置（`src/content/` 下的 JSON/TXT）——可转换为 Unity Addressable 或内置资源
- 应用导航状态机（`src/app/`）——可保留为 Unity 加载前的 HTML 壳页面，或完全用 Unity UI 重写
- 测试逻辑（单元测试用例可移植为 C# Test Framework）

### 1.3 Unity 环境搭建（接手方自行完成）

接手方需要在本地安装以下软件（Windows 11）：

```
1. Unity Hub（最新版）
2. Unity 2022.3 LTS（URP 模板，带 WebGL 构建模块）
3. Visual Studio 2022（含"Unity 游戏开发"工作负载）
4. Blender（最新版，用于模型获取与修改）
```

安装步骤：
1. 下载 Unity Hub：https://unity.com/download
2. 安装 Unity Hub 后登录 Unity 账号（免费个人账号即可）
3. 通过 Hub 安装 Unity 2022.3.48f1 LTS（或更新 LTS），勾选 **WebGL build support** 和 **C# support**
4. 安装 Visual Studio 2022 Community，工作负载选择 **"Unity 游戏开发"**
5. 下载 Blender：https://www.blender.org/download/，安装到 `C:\Program Files\Blender Foundation\Blender\`
6. 在 Unity 中创建新项目，选择 **3D (URP) Template**，项目名 `Campaign1934`
7. 安装以下 Unity Package（通过 Package Manager 或手动导入）：
   - `com.unity.inputsystem`（新版输入系统，支持键盘 + 鼠标）
   - `com.unity.test-framework`（单元测试）
   - `com.unity.addressables`（资源管理，用于加载外部素材）

> **注意：** Unity 安装约 15–25 GB 磁盘空间，Blender 约 500 MB，首次安装需 30–60 分钟，取决于网络。

### 1.4 开发过程中缺什么软件，AI 直接下载在合适地方

> **核心原则：AI 自行判断需要哪些工具，自动下载安装到合适位置，不需要等待用户确认。**

开发过程中 AI 可能需要的软件及安装位置：

| 软件 | 用途 | 安装位置 |

1. 发现需要某个软件 → 检查是否已安装 → 未安装则自动下载

4. 下载源优先官方渠道，其次可信镜像站
5. 下载完成后自动配置到可用状态，继续下一步开发

## 2. 素材约定（先记住这三条）

1. **素材授权要求：所有外部素材必须使用 MIT 授权。** 项目本身采用 Apache 2.0，MIT 是其子集，完全兼容。项目方已提供的素材（`public/assets/` 下）授权状态以 `docs/ASSET_LICENSES.md` 为准，后续新增素材一律遵循 MIT。
2. **素材来源优先级：**
   - ① 项目方提供（`public/assets/` 和 `art/` 目录，fork/clone 即可获取）
   - ② Unity Asset Store 中筛选 **MIT 授权** 的模型/纹理/音频
   - ③ 其他 MIT 资源站（如 [Kenney.nl](https://kenney.nl/assets) 部分素材）
3. **MIT 素材无法直接找到完全符合 1934 年中国军事题材的模型。** 这是客观现实——MIT 素材库里没有现成的"红军灰蓝军装+红袖标"或"国民党军土黄军装+德式头盔"。接手方需要：
   - **获取模型全由 AI 完成**：AI 从 Unity Asset Store 筛选 MIT 授权的通用士兵模型包下载
   - **改模型全由 AI 完成**：AI 在 Blender 或 Unity 中修改服装颜色、添加红袖标、更换头盔形制、调整装备
   - 参考 `public/assets/reference/ref_model_soldier_red.jpeg` 和 `ref_model_soldier_kmt.jpeg` 确保外观准确
   - 参考 `battle.mp4` 和 `battle 02.mp4` 确保整体美术风格统一
4. **素材未到位时，先做占位实现**：路径集中配置，媒体缺失时降级到程序化占位，不要阻塞功能开发。
5. **不要替换或删除项目方提供的素材文件**，也不要自行引入任何外部素材（除非确认 MIT 授权）。

| 类型 | V1 位置 | V1.1 Unity 位置 | 命名 |

## 3. A 组 · 音频

### A1 导读页背景音乐

- 音乐：情绪激昂的纯音乐（红色题材风格），伴奏循环，首尾各 2 秒淡入淡出。
- 范围：导读页与总览页播放；进入战斗场景时停止并释放。
- 播放时机：必须在用户首次交互后才能开始（浏览器自动播放策略），首次点击或按键时解锁 AudioContext 并起播。
- 实现位置：**Unity 音频系统**——使用 `AudioSource` + `AudioClip`，在 Unity UI 的导读页挂载 `AppAudioManager` 脚本控制。
- 控件：导读页提供静音/恢复按钮，不遮挡正文与底部按钮，状态存 `PlayerPrefs`（对应原 localStorage）。
- 验收：导读页停留 3 分钟无爆音、无卡顿、循环接缝无咔哒声；静音按钮即时生效；进入战斗后音乐完全停止。

### A2 战役卡片悬停音效

- 可进入卡片（飞夺泸定桥）：短促清亮的音效，时长 ≤ 0.25 秒。
- 锁定卡片（其余 5 张）：明显不同的低沉短音。
- 节流：200ms 内不重复触发，鼠标快速划过多张卡时不连成一片。
- 键盘 Tab 聚焦时触发同样音效（无障碍）。
- 验收：快速划过 6 张卡只触发有限次数；音量明显低于战斗音效。

### A3 玩家枪声音量

- 问题：默认音量下玩家射击声偏轻，质感偏弱。
- 原因（原 `AudioManager.ts`）：玩家枪声是 Web Audio 程序化合成，而远处枪声用的是 CC0 采样 `guns.mp3`，两者质感不一致；且环境底噪叠了三层循环噪声，盖住了枪声。
- 要求：
  ① 近距射击改用与 `guns.mp3` 一致的采样质感（或叠加一层采样）；
  ② 新增独立的 Weapon 子总线，使枪声可脱离环境音单独调节；
  ③ 保留连发间隔，不得因提高音量产生爆音或削波。
- 验收：默认设置下连发时枪声清晰盖过风雨/河水底噪；连续射击 30 发无爆音、无卡顿。

### A4 战斗环境音增强

- 炮弹落地爆炸：把爆炸音效**绑定到炮击落点**，按落点距离做音量衰减与声像定位（Unity 3D Audio），取代现在"背景里响一声"的做法。
- 冲锋呐喊：红军发起冲锋时触发。每波冲锋触发一次，8 秒内不重复，音量不超过爆炸声。播报期间遵循 ducking 规则降到约 40%。
- 验收：炮弹落点与爆炸声位置一致；呐喊不抢戏、不循环轰炸耳朵。

### G1 炮弹飞行轨迹（已实现）

- 炮弹不再从目标正上方竖直下落，而是**从国民党军方向（桥对岸，Z 轴正方向）划弧线飞来**，飞行距离约 18–30 米。
- 高度按抛物线下降（`artilleryShellHeight`），水平方向线性插值，形成可见的飞行弧线。
- 实现位置：`src/battle/core/artillery.ts` 新增 `artilleryShellPosition` 函数；`src/battle/three/SceneFactory.ts` 使用新函数更新炮弹位置。

## 4. B 组 · 人机动效

### B1 静止/卡住时停止奔跑动作

- 问题：人机撞到障碍物或静止不动时，腿部仍在摆动。
- 根因（原 `BotManager.ts:269`）：`setMoving` 按 `distance > 0.4 && state === 'advance'` 判断。撞墙时 `targetZ` 仍有距离，所以位移被挡住了腿还在摆。
- 要求：实际位移连续 0.3 秒低于 0.05 米时，强制停止腿部摆动与上身起伏。
- 验收：把人机逼到树/房屋/垃圾箱前，1 秒内腿部动作归零；脱困后恢复正常。

### B2 新增下蹲、匍匐姿态

- 在 Unity 中为人机模型添加 `stand/crouch/prone` 三种姿态动画状态。
- 速度倍率：下蹲约 0.5，匍匐约 0.25。
- 碰撞盒本次不做改变，只做视觉表现，避免动到命中判定、破坏战斗平衡。
- 验收：三种姿态在 30 米外可分辨；切换平滑无抖动；15–20 人机同场下帧率不低于 30 FPS。

### B3 撞到障碍物时的躲避决策

- 规则：撞到障碍物时，50% 概率下蹲躲避，50% 概率站立绕行（概率写成可配置常量，便于调手感）。
- 下蹲躲避持续 0.8–1.5 秒后恢复推进；绕行则侧向移动后再推进。
- 验收：观察 10 次撞击两种行为都出现，不出现原地卡死超过 2 秒。

### B4 过桥时的奔跑/匍匐混合

- 桥面冲锋中的红军人机，约 2/3 快速奔跑、约 1/3 匍匐前进。
- 验收：桥面上能同时看到两种姿态，比例大致符合。

## 5. C 组 · 过桥节奏（已定的设计取舍）

### C1 冲锋节奏

- 桥面段红军人机速度从当前 1.25–1.8 m/s 提高到 **3.2–4.0 m/s**。
- 编组：每次投入 **2–3 人**向前冲；前方倒下后 0.8–1.5 秒补上下一组。
- 桥上红军同时存在人数**硬上限 5 人**；达到上限后后续编组在桥头待命，不提前上桥。
- 验收：任意时刻桥面红军 ≤ 5 人；能看到"冲上去——倒下——再冲上去"的连续节奏。

### C2 "受挫"的表现方式（已定，不再靠减速）

- 阶段 2 的剧本是"第一波突击受挫"，但提速后不能靠"冲得慢"来表现受挫。
- **改用**：投入的编组大量倒在桥面 + 推进距离长时间停滞在桥中段。
- 桥面段总时长（阶段 2 + 阶段 3）需与新节奏重新对齐。
- 约束：单局总时长控制在 ≤ 10 分钟。

## 6. D 组 · 阶段过渡

### D1 丛林阶段：打完再走

- 现状：`phase_1` 为 `durationSec: 50`、`endCondition: 'timer'`，导致红军还没打到桥头就切到下一阶段。
- 修改：
  ① 丛林阶段时长延长到约 90 秒；
  ② 结束条件从"计时"改为"丛林守军被清空 **且** 红军前锋推进到桥头"；
  ③ 丛林段国民党军停止增援（当前配置 `initial: 12, reinforcements: 8`），"全部杀掉"指这 12 名初始守军；
  ④ **必须保留超时兜底**：90 秒仍未达成条件时强制进入下一阶段。
- **为什么必须保留兜底**：PRD AC-09 要求玩家完全不操作时剧本仍要走完并胜利。改为状态条件后，玩家挂机且红军清不完敌人就会卡死在丛林段。
- 引导：用字幕与任务提示引导玩家向桥头移动，不要使用火炮驱赶。
- 验收：正常推进下看到守军被清空并抵达桥头后再过渡；挂机 90 秒后仍能自动进入桥面段。

### D2 碉堡 → 街巷：先锋冲入过场

- 现状：从"进攻碉堡"直接切到"街道肃清"，过渡生硬。
- 修改：在阶段 3 末尾/阶段 4 开头插入 6–10 秒过场——
  2–4 名红军突击队员从桥头冲入碉堡，与内部守军短兵相接，随后主力跟进进入街巷。
- 玩家处置：过场期间**临时禁用**"脱队被拦截/炮击"的惩罚；
  玩家若停留在桥面，用字幕与战友喊话引导，不要用火炮驱赶。
- 验收：能看清先锋冲入碉堡的过程；过场期间玩家不会被惩罚；过场不卡死。

## 7. E 组 · 场景内视频投影（本次新增）

### E1 呈现形式

- 使用 Unity `VideoPlayer` 组件将视频贴在场景物体表面（`RenderTexture` + `MeshRenderer`）。
- **不做**全屏叠加、**不做** HUD 角落小窗。
- 理由：全屏叠加要同时跑视频解码和 3D 渲染，会把 40 人机的场景拖到 30 FPS 以下；场景内投影对帧率几乎无影响，也不打断指针锁定。
- 内容主题：项目方自制/AI 生成的战役画面。项目整体走写实路线，视频与 3D 场景都应写实、风格统一。

### E2 屏幕绑定剧情，不固定常亮

三块屏幕物理位置固定，但**只在对应剧本阶段点亮播放**，其余时间熄灭。玩家推进到哪一段，哪一块屏幕亮起——影像跟着剧情走，而不是固定在原地常播。

| 剧本阶段 | 点亮的屏幕 | 位置 |
| | --- | --- |
| 阶段 1 丛林接敌 | 丛林宣传牌 | 丛林区域，需新建立式牌面 |
| 阶段 2/3 桥面突击 | 对岸碉堡正面墙 | 碉堡墙面 |
| 阶段 4 街巷肃清 | 街巷房屋墙面 | 街巷区域 |

- 切换时机：挂在阶段切换事件上——阶段切换时，上一块屏幕淡出熄灭，当前阶段对应的那块淡入亮起。
- 如果希望"同一块屏幕在不同阶段播放不同影像"，按 `vid_phase_1..4.mp4` 命名素材，另计。

### E3 技术要求

- `VideoPlayer` 必须设置 `renderMode = VideoRenderMode.RenderTexture` + `loop = true` + `source = VideoSource.Url`。
- **视频本身静音**，声音由 Unity AudioMixer 单独处理，避免与战斗音效冲突。
- 只创建 3 个 `VideoPlayer`，不做动态增删。
- 距离 > 60 米时暂停该视频播放以省性能。
- 非当前阶段的屏幕不播放视频（只显示静态底图或熄灭），降低显存与解码占用。
- 阶段切换时屏幕用约 0.5 秒淡入淡出，不要硬切。
- 素材未到位时，用 `RawImage` + 纯色材质生成占位画面。
- 验收：每段都能看到对应屏幕亮起；阶段切换有过渡；战斗全程帧率不低于 30 FPS。

## 8. F 组 · 视觉方向：照片级真实

> **方向已定（2026-10-24）：采用方案 B——Unity WebGL，照片级真实。**
> 本节是对 `PRD.md` FR-3.6「风格化低多边形」的有意推翻，接手方必须同步更新 PRD。

### F1 为什么选 B

- 「照片级真实」「网页免安装」「40 人机 30+ FPS」三者不可兼得。
- Unity URP/HDRP 内置写实渲染管线，开箱即支持 PBR 材质、HDR 光照、后处理（bloom、SSAO、film grain、暗角、色调映射）。
- 现有战斗逻辑（`src/battle/core/`）可移植为 C#，保留全部导演规则、胜利保障和测试。
- WebGL 导出后仍是网页形态，可部署到 GitHub Pages 或任意静态托管。
- 方案 C（Unreal/原生桌面）放弃网页形态，代价过大——**已放弃**。

### F2 照片级真实的具体做法

- **模型**：红军/国民党军士兵、铁索桥、碉堡、山体、河流、街巷房屋，使用写实 PBR GLB 模型（albedo/normal/roughness/metalness/ao 贴图 + 骨骼动画）。
- **光照**：HDR 环境光（HDRI 贴图）+ 方向光（模拟太阳）+ 半球光（天光反弹）+ 体积雾。
- **后处理**：Unity URP Post-processing Volume，启用 bloom、SSAO、film grain、暗角、色调映射（ACES）、色温/饱和度微调。
- **材质**：所有表面使用 PBR 材质，金属/粗糙度/法线贴图齐全。铁索桥的锈蚀金属、河岸的泥土岩石、街巷建筑的墙面都有对应的纹理。
- **UI/HUD**：随场景写实化协调调整，保持庄重，避免廉价满屏红（PRD FR-1.3）。

### F4 性能红线（写实后最吃紧的一条）

- 「15–20 人机同场不低于 30 FPS」是写实后的硬约束。写实模型面数高得多，无法维持 V1 的 40 人机。
- 相应更新 PRD 的人数约束（VR-1、AC-07）：同场人机 15–20 名，红军约 10–14 名，国民党军约 5–8 名。
- 这是写实路线下的唯一让步，人数下限需用户确认后再动。
- Unity WebGL 优化手段：
  - 士兵使用 GPU Instancing（同模型不同材质通过 Material Property Block 区分）
  - 远处士兵使用 LOD（Level of Detail），>50 米切换低模
  - 遮挡剔除（Occlusion Culling）
  - 限制每帧最大光源数（使用 baked 光照代替 real-time）
  - WebGL 构建时启用 `Compression` 和 `Compression` 选项

### F5 内容与史实红线

- 无断肢、无喷血，倒地/受击表现克制（`PRD.md` §7.7）。写实后更易踩线，务必克制。
- 历史表述仍以权威公开资料为准（`PRD.md` §5.6）。

## 9. 交付要求

- **分组提交**：A 音频 → B 动效 → C 桥面节奏 → D 过渡 → E 视频 → F 写实化。
  F 组只动渲染层和模型，不要碰 `src/battle/core/` 的战斗逻辑（移植为 C# 后放在 Unity 项目的 `Scripts/Core/` 下）。

  涉及导航/阶段切换时补跑 `npm run test:e2e`（Playwright 测试 Unity 构建的 HTML 壳）。
- 新逻辑优先写成 `Scripts/Core/` 下的纯 C# 类并补单元测试（架构约定见 `HANDOFF.md` §5）。
- 素材路径集中配置，不要散落在业务代码里。
- 完成后更新 `README.md` 的变更说明，并明确指出哪些改动需要人工验证手感。

## 10. 与 V1 的差异对照

| 维度 | V1（Three.js） | V1.1（Unity WebGL） |
| | --- | --- |
| 渲染引擎 | Three.js r0.186 | Unity 2022.3 LTS（URP） |
| 视觉风格 | 风格化低多边形 | 照片级真实（PBR + HDR + 后处理） |
| 音频 | Web Audio API（程序化合成 + CC0 采样） | Unity AudioMixer（采样为主） |
| 构建工具 | Vite + TypeScript | Unity WebGL Build + HTML 壳 |
| 测试 | Vitest + Playwright | Unity Test Framework + Playwright |
| 部署 | `dist/` 静态文件 → GitHub Pages | `Build/WebGL/` 静态文件 → GitHub Pages |
| 战斗逻辑 | TypeScript（`src/battle/core/`） | C#（`Scripts/Core/`，从 TS 移植） |
| 应用导航 | TypeScript DOM（`src/app/`） | Unity UI 或 HTML 壳 + Unity Scene |
| 本地开发 | `npm run dev` | Unity Editor 播放 + `npm run dev`（HTML 壳） |
